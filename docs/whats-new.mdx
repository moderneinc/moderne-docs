  links={[{ label: 'Code Search reference', to: '/user-documentation/agent-tools/code-search' }]}

Code Search arrived in the Moderne Platform in preview last month. Video demos now show it in action, including finding every repository on older Spring versions and tracing a field through COBOL copybooks.

* **ColdFusion support.** ColdFusion repositories can now be built into LSTs, so you can search and run recipes on them as well.
* **Case-insensitive by default.** Search now ignores case, matching how COBOL and ColdFusion behave. Add `case:yes` to a query when you need an exact match.
* **Coming next month.** Code navigation lets you jump from a search result to its definition and follow a symbol across repositories.

Code Search is part of our approach to recursive self-improvement. An agent scopes a change, writes a recipe, then fixes the recipe with every build or test failure, so the recipe's coverage grows with every pass.

<WhatsNewEntry
  product="agents"
  kind="Feature"
  title="Start your coding agent on a whole organization"
  links={[{ label: 'Agent chat guide', to: '/user-documentation/agent-tools/agent-chat' }]}
>

Coding agents usually work inside one repository at a time. The new `mod <agent> chat` command in the Moderne CLI (4.8.4 and later) starts your agent at the root of an organization you've synced, so a single prompt can cover every repository in it.

Pass it an organization name and a prompt, and the CLI starts your agent of choice at the root of that organization's repositories with Moderne's instructions for working across many of them. The agent looks for a tested recipe first, then spends its own effort checking the results and handling whatever the recipe didn't cover.

```bash
mod claude chat . --org "My org" --prompt "Upgrade these repositories to Java 25"
```

This is our recommended approach for running agents with Moderne locally. Local MCP is still available, but we consider it experimental. It only works in one repository at a time, and agents often reach for their own built-in search and edit tools instead of Moderne's. With `mod <agent> chat`, agents keep their own tools and use the Moderne CLI for what those tools can't do, like running a recipe across an entire organization.

</WhatsNewEntry>

<WhatsNewEntry
  product="openrewrite"
  kind="Recipes"
  title="Find duplicated and similar code with Prethink"
  links={[{ label: 'Moderne Prethink', to: '/user-documentation/agent-tools/prethink' }]}
>

Coding agents like to copy and paste, spreading near-identical code that adds verbosity and complexity, and vulnerable patterns along with it. Two new zero-AI recipes add duplication detection to Prethink as precomputed context, so an agent reads a clone map instead of searching for one.

* **FindDuplicateCode.** Fingerprints LST subtrees to catch exact, renamed, and gapped clones, even when a statement or two has been inserted or removed between copies.
* **FindSimilarCode.** Uses MinHash and LSH to catch fuzzy near-duplicates that exact matching misses.
* Both run across Java, Kotlin, Groovy, C#, and Python and emit queryable data tables. Every occurrence carries a stable ID that a follow-on recipe can act on.

</WhatsNewEntry>

<WhatsNewEntry
  product="openrewrite"
  kind="Recipe"
  title="Make your Java codebase null-safe"
>

Enabling a null-safety checker like NullAway starts with annotating every API as nullable or non-null. Nullability isn't local, though. It flows across methods, files, and dependency edges. The new `NullSafety` recipe analyzes null flow across the entire codebase, infers and adds JSpecify annotations where they can be verified from the code itself, and automatically repairs provable violations.

* Every change is behavior-preserving and suppression-free.
* Anything that can't be confirmed safe is returned as a short review list.
* The result is a codebase ready for a checker to enforce.

</WhatsNewEntry>

<WhatsNewEntry
  product="openrewrite"
  kind="Security"
  title="When a critical CVE drops, recipes are your fast path to safety"
>

CVE-2026-22732 is a 9.1 critical vulnerability in Spring Security that drops crucial HTTP security headers, leaving web applications exposed to attacks like clickjacking and cross-site scripting (XSS). Moderne had a detection and remediation recipe running four hours after it was disclosed.

The vulnerability is subtle. It silently strips security headers (`X-Frame-Options`, `Strict-Transport-Security`, `Cache-Control`) when applications commit responses early. Standard pattern-matching tools may catch the obvious cases but miss the harder ones, like streams factored into helper methods, streams stashed on instance fields, or subclass overrides.

* **FindSpringSecurityHeaderSuppression** uses taint-flow analysis to track all five suppression patterns interprocedurally, across method boundaries, fields, and type hierarchies.
* It produces structured findings joined with per-project Spring Security version data, then composes directly with `UpgradeDependencyVersion` to patch affected projects to safe versions (5.7.22 through 7.0.4) in a single run.
* New taint-tracking injection recipes, `FindLogInjection`, `FindArrayIndexInjection`, `FindJndiInjection`, `FindUnsafeReflectionInjection`, and `FindProcessControlInjection`, are all included in the Remediate OWASP A05:2025 Injection composite recipe.
