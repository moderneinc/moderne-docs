<RecipeHeader.Title>Say which build orders the scheduler does not enforce, and which jobs nobody orders</RecipeHeader.Title>

<RecipeHeader.Description>Reconcile the scheduler against the build and against the JCL library. A link-edit deck that includes an object binds whatever the object library held when the binder ran, so the job that compiles the object has to have run before the job that links the module: a row per order the build requires, with the job that writes the object, the job that reads it, the schedules that submit each, and whether a condition puts them in that order. The second table is the library from the job's side: every JCL member with the schedules that submit it, and the members nobody orders. A third finding is the reference no deck accounts for: a name an assembler member uses and defines nowhere that no `INCLUDE` card names is one the binder's autocall resolves, so what the module holds is whatever `SYSLIB` held on the day it ran. `FindScheduleGaps` answers the same question and marks the cards and job names it was answered from; this one produces the tables and changes nothing.</RecipeHeader.Description>

</RecipeHeader>
